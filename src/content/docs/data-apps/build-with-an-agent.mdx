An AI agent on your computer can build a Keboola app from one prompt. With the `dataapp-developer` plugin from Keboola's [AI Kit](/ai/ai-kit/), it reads your data, writes the code, creates the app with a Git repository that Keboola manages, pushes the code there and deploys it. You end up with a running app at its own URL, and the code in a repository you can keep changing.

To build inside Keboola instead, [Kai](/data-apps/getting-started/) does the same from the **Create App** screen, with a live preview. To write the code yourself in your own repository, see [Build an app locally](/data-apps/build-locally/).

## Before you start

- A Keboola project with the data the app should show.
- [kbagent](/cli/), connected to that project. The agent runs it to create, deploy and inspect the app. Creating the push token for the app's repository needs admin rights in the project.
- An AI client: Claude Code, Claude Desktop, Cursor, VS Code or the ChatGPT app. Using another agent? See [Other agents](#other-agents).

The agent can't set up single sign-on for the app. `kbagent data-app create` offers a shared password or a public app, and a new app gets the password. You can switch it to SSO later under [Authentication](/data-apps/authentication/).

## Describe the app

Say what the app shows, which data it uses and where the code goes, and ask for a new, deployed app. Without the word *new*, the skill prefers changing an app that already exists. For example:

```text
Build a Keboola app that shows the number of orders per day as a line chart,
from the orders table in my project. Put the code in a new Keboola-managed Git
repository, deploy the app, and give me its URL.
```

The agent reads the skill, finds the table and queries a sample before it writes any code. Name a framework if it matters to you; for a dashboard, the skill defaults to Node.js with Chart.js. Claude Code asks you to approve each command it runs unless you've allowed them. To use your own GitHub repository instead, put its URL in the prompt; the repository then has to follow the layout in [Build an app locally](/data-apps/build-locally/).

These are the commands the agent runs on the managed-repository route, and you can run them yourself. `<alias>` is your project's name in kbagent; `kbagent project list` shows it in the **Alias** column. `create` prints the app ID and the config ID, and `git-repo` prints the HTTPS URL of the repository.

```bash
# Create the app with an empty Keboola-managed repository
kbagent data-app create --project <alias> --name "Orders per day" --slug orders-per-day --use-managed-git-repo

# Get the repository URL and a push token (the token is shown only once)
kbagent data-app git-repo --project <alias> --app-id <id>
kbagent data-app git-credentials-create --project <alias> --app-id <id> --type http_token --permissions readWrite --yes

# Push the code to main; when Git asks, use any username and the token as the password
git push <https-url> main

# Deploy and wait until the app runs
kbagent data-app deploy --project <alias> --app-id <id> --wait
```

An app created with a managed repository isn't deployed yet, because its repository is still empty. By default it gets password sign-in, the `tiny` size, sleep after 15 minutes without visitors, and access to Storage.

### The MCP route

Through the Keboola MCP server, the agent doesn't run kbagent. It calls the server's app tools instead, such as `modify_python_js_data_app`, `create_python_js_data_app_git_credential` and `deploy_data_app`:

- It creates the app with a Keboola-managed repository, and a draft of it next to the production app.
- The draft runs in development mode at its own URL, so you preview the app before anything goes live. If the repository has a `keboola-config/supervisord-dev/` program, the draft reloads each push within seconds; otherwise the agent redeploys it.
- The production app stays undeployed until you approve the draft. Then the agent merges the draft into production and deploys it.
- The repository block is in the configuration from the start, so [the workspace bug](#if-the-app-cant-read-storage) doesn't apply.

## Check the app

- The agent finishes with the app's URL.
- The app asks for its password. The agent usually can't show it, because `kbagent data-app password` needs a Manage API token. Open **Apps** from the left navigation and then your app: once it's deployed, the password is next to **Open App** (see [Authentication](/data-apps/authentication/)).
- If the app opens without data, read its log with `kbagent data-app logs --project <alias> --app-id <id>`. If it doesn't start at all, `kbagent data-app runs --project <alias> --app-id <id>` shows why. [Troubleshooting](/data-apps/troubleshooting/) lists the common causes, including `Promise.withResolvers is not a function` from a too-new `@keboola/api-client`.

### If the app can't read Storage

Until [keboola/cli#765](https://github.com/keboola/cli/pull/765) ships (kbagent 0.94.0 and earlier), an app created with `--use-managed-git-repo` gets no workspace, however often you redeploy it with kbagent. It runs, but its code finds no `WORKSPACE_ID`. An app built from the plugin's Node.js template logs `Missing env vars: WORKSPACE_ID (or KBC_WORKSPACE_MANIFEST_PATH)`.

The app's configuration is missing its repository block. Add it, before the first deploy or after it, and deploy:

```bash
kbagent config update --project <alias> --component-id keboola.data-apps --config-id <config-id> --merge --configuration '{"parameters":{"dataApp":{"git":{"repository":"<https-url>","branch":"main","private":true}}}}'
kbagent data-app deploy --project <alias> --app-id <id> --wait
```

If you no longer have the config ID from `create`, `kbagent --json data-app detail --project <alias> --app-id <id>` shows it as `config_id`. After the fix ships, `deploy` adds the block itself.

## Change the app later

Ask the agent for the change. It edits the code, pushes it to the same repository and runs `kbagent data-app deploy --wait` again; the app restarts on each deploy. In a new session, the agent gets the repository URL from `kbagent data-app git-repo` and a fresh push token from `git-credentials-create`. To edit the code yourself, clone the repository from that URL with a push token.

Stopping and waking the app, secrets, settings and deleting are in [Operate and update an app](/data-apps/operate/). kbagent has no commands for drafts or copying an app, and `kbagent data-app deploy --config-version` runs an older configuration for one deploy without restoring it. Drafts, copying and a real [rollback](/data-apps/operate/#see-what-changed-and-go-back) happen in the Keboola UI.

## Other agents

Any agent that can run shell commands can drive kbagent with the commands on this page. For the push, it has to hand Git the token without a prompt, for example through a credential helper, because an agent's shell can't answer one. Have it load kbagent's full command reference with `kbagent context` first ([the context reference](/cli/for-agents/#the-context-reference)). If the agent can't install plugins, give it the skill as files: the folder is [on GitHub](https://github.com/keboola/ai-kit/tree/main/plugins/dataapp-developer/skills/dataapp-development), with the app templates and reference guides the skill points to.
