Your data lives in more places than one: files, a spreadsheet someone keeps, an API, a database.
Keboola is where you bring it together and shape it with SQL. Once you have a project, Kai, its AI
assistant, can do the work from what you tell it in plain language: it loads your data, answers
questions about it, and turns the answer into an app, asking for your approval along the way. The
pipeline then reruns by itself every week. This guide does each of those once, on a small sample,
so you can do them on your own data.

The sample is six cafés: five files (a summer of sales, the rosters, the weather) and next week's
forecast from a public API that needs no account. The moves are the same on your own tables. Every
step works toward one question: **Which day next week will leave a café short-handed?** By the
fifth page a grid answers it, and every Monday the answer is rebuilt on the new forecast. The grid
is one kind of app; Kai builds interactive dashboards and what-if simulators the same way, from a
description you write ([What you can build](/data-apps/what-are-apps/#what-you-can-build)).

## How every page works

Every page with a task on it offers that task three ways:

- **Prompt**: paste it into **Kai Agent**, the assistant in the project's top bar, and watch it build.
  [Create or join a project](/getting-started/project/#check-it-worked) says how to tell you have it.
- **UI**: the same task click by click, to see where each setting lives.
- **CLI / API**: the same task from a terminal with [kbagent](/cli/), with the raw request where
  there is no command for it.

Pick a tab once and every page after it opens on the same one:

![Choosing the CLI / API tab on one page, then opening the next page in the guide, which is already showing its CLI / API tab](/getting-started/tab-sync.gif)

Where one of the three cannot do the job (a signup form, a Google consent screen, a branch merge),
the page says so rather than showing an empty tab.

### Approvals and plan mode

{/* Moved here from PathIntro.astro on 2026-09-29: the component printed this on every task page
(179 words each, the block in David Esner's screenshot). Every page links here now. */}

**In the chat, Kai asks before each change it makes:** an approval card shows exactly what it is
about to write or run, with **Approve**, **Decline** and **Always allow**. Questions that only read
do not ask, and neither do tools set to **Always allow**; a new account has two write tools set
that way, both for apps. In the chat, an approval left unanswered for about five minutes counts as
declined: Kai says so, and you ask it to try again. The Apps builder asks less: it builds a draft
of the app, code and preview included, without asking, and when you publish it asks twice, once
for the app's access to Storage and once to deploy it.

<details>
<summary>Fewer approvals, plan mode, and undoing a step</summary>

- **If confirming each one gets tiring,** pre-approve tools in
  [tool permissions](/kai/settings/#tool-permissions): the gear in the Kai panel, then **Tools**.
- **Plan mode is a different thing.** With **Plan mode** from the **+** menu in the chat's message
  field, Kai writes the steps down and asks you to approve the plan before it starts, and then
  still asks for each change. Use it when you want to read the plan first, not to save clicks.
- **Most of it can be undone.** If a step builds something other than the page describes, say so
  in the same Kai chat, or edit the configuration by hand. Every configuration Kai creates or
  changes keeps a **Versions** tab, and **Restore this version** on an earlier row takes it back;
  **Delete configuration** removes one you do not want, into **Trash**. Restoring a version changes
  the configuration only: tables a job already wrote stay as they are. The weekly schedule is a
  configuration of its own, outside the flow's versions, and an app's versions record its
  settings, not the code Kai wrote.

  ![Screenshot - The Versions tab of the Boolabean sales configuration: one version per change Kai made, from Configuration created to the fifth row added, with the Restore this version tooltip on an earlier row](/getting-started/kai-undo-versions.png)

</details>

## If you are planning a rollout, not learning the tool

This guide is for one person building one pipeline. For introducing Keboola to a team, with
project architecture, a data model, naming conventions and governance, start with
[Platform Onboarding](/overview/onboarding/) instead.
